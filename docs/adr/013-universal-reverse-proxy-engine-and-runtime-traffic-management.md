# ADR-013: Universal Reverse Proxy Engine & Runtime Traffic Management

## Status

Accepted

## Date

2026-07-03

## Context

Prior to V5 Milestone 4B.3, reverse proxy configuration and routing management in Deployrix had critical architectural flaws:

1. **Source Code & Asset Mutation** — Legacy code attempted to patch HTML, rewrite JavaScript bundles, or inject runtime scripts into built frontend applications to accommodate proxy pathing.
2. **Coupled Proxy Implementations** — Routing logic was tightly bound to Nginx-specific directives, preventing seamless integration of alternative reverse proxies such as Caddy or Traefik.
3. **Implicit & Hardcoded Routes** — Proxy paths were guessed from repository scans rather than derived deterministically from immutable deployment contracts.
4. **Fragile Rollbacks** — Proxy rollbacks mutated application files or restarted container services unnecessarily.

## Decision

We introduce the **Universal Reverse Proxy Engine V5** (`ReverseProxyEngineV5`), **Reverse Proxy Model** (`ReverseProxyModel`), decoupled Routers (`RouteResolver`, `AssetRouter`, `ApiRouter`, `OAuthRouter`, `WebSocketRouter`, `HistoryFallbackRouter`), and independent Policies (`CompressionPolicy`, `CachePolicy`, `HeaderPolicy`, `TLSPolicy`) with the following mandatory architectural rules:

> 1. **Reverse proxy behavior is derived exclusively from immutable runtime contracts (RuntimeManifest, CompatibilityContract, AssetManifest) and never from repository inspection or framework-specific heuristics.**
> 2. **Applications are immutable after build. All traffic adaptation occurs in the reverse proxy layer, not by modifying application artifacts.**
> 3. **Reverse proxy adapters (Nginx, Caddy, Traefik, Envoy, HAProxy) must consume the same ReverseProxyModel, ensuring proxy-agnostic behavior.**
> 4. **Traffic routing, static assets, APIs, OAuth callbacks, WebSockets, TLS, compression, caching, and security headers are independent policies that compose into the final proxy configuration.**
> 5. **Reverse proxy generation must be deterministic, idempotent, and fully reproducible from immutable deployment contracts.**

### Key Architectural Principles

1. **Zero Runtime Mutation** — Deployrix NEVER rewrites application source code, NEVER patches JavaScript bundles, NEVER modifies HTML, and NEVER injects runtime scripts. Applications are immutable after build; the reverse proxy adapts to the application.
2. **Single Immutable ReverseProxyModel** — All proxy adapters (`NginxAdapter`, `CaddyAdapter`, `TraefikAdapter`) consume the identical `ReverseProxyModel` generated by `ReverseProxyEngineV5`.
3. **Capability-Driven Routers & Policies** — Dedicated routers compose application routes, asset routing, API routing, OAuth redirects, WebSocket upgrades, and SPA HTML5 history fallbacks into unified configuration blocks.
4. **Targeted Proxy Rollbacks** — Proxy rollbacks ONLY restore previous proxy configurations and NEVER restart containers, databases, or applications.

### Architecture

```
ExecutionGraph Node [reverse-proxy-node]
                 │
                 ▼
  ReverseProxyEngineV5
                 │
                 ├─► Routers (RouteResolver, AssetRouter, ApiRouter, OAuthRouter, WebSocketRouter, HistoryFallbackRouter)
                 │
                 ├─► Policies (CompressionPolicy, CachePolicy, HeaderPolicy, TLSPolicy)
                 │
                 ▼
  ReverseProxyModel (Single source of truth)
                 │
                 ├─► NginxAdapter
                 ├─► CaddyAdapter
                 └─► TraefikAdapter
                 │
                 ▼
  RuntimeContext (ReverseProxySnapshot & ProxyReports)
```

## Consequences

### Positive

- Guarantees 100% application immutability post-build; zero risks of corrupted JavaScript or HTML assets.
- Provides true proxy-agnostic portability across Nginx, Caddy, Traefik, Envoy, and HAProxy.
- Eliminates OAuth routing failures by explicitly supporting `/login`, `/oauth`, `/callback`, `/auth`, `/auth/*`.
- Deterministic and idempotent reverse proxy configuration generation.

### Negative

- Every new proxy provider must implement the `ReverseProxyAdapter` interface.

### Migration Path

Activated in `V5_PRODUCTION` engine profile via `ReverseProxyModuleV5` adapter connected to `ExecutionGraph`.
